## 李跳跳是什么？

一款用来跳过**开屏广告**和**弹窗**的安卓应用。

## 李跳跳的原理？

利用安卓系统的**无障碍**权限，帮助用户**自动点击**广告上的**跳过按钮**。

> 💡 **无障碍权限是什么？** 可以理解为安卓系统为视障人士提供的辅助功能。开启后，App 可以帮你“看”屏幕上有什么，并模拟点击操作。李跳跳就是用这个权限来帮你自动点击广告上的“跳过”按钮。

## 自定义规则

> 如果你只想跳过广告，**不需要手动写规则**。以下内容适用于默认规则无法跳过的特殊情况。

### 1. 开屏广告规则

```json
{"keywords":["xxx"]}           // 完全覆盖默认规则
{"keywords_append":["xxx"]}    // 在默认规则基础上追加
```

**什么时候用？** 默认规则跳不过某个 App 的开屏广告时。

**`xxx` 填什么？** 填写广告“跳过按钮”的特征，可以是以下三种之一：

| 类型 | 说明 | 示例 |
|------|------|------|
| 文案 | 按钮上的文字 | `{"keywords":["关闭广告"]}` |
| id | 按钮的唯一标识（由 App 开发者设定） | `{"keywords":["tv_close_button"]}` |
| bounds | 按钮在屏幕上的位置和大小（四个数字分别代表：左、上、右、下坐标） | `{"keywords":["900,160,1170,250"]}` |

👉 [点击跳转：什么是 id 和 bounds？](#什么是控件的-id-和-bounds)

**参数对比：**

| 参数 | 行为 | 适用场景 |
|------|------|----------|
| `keywords` | 覆盖默认规则 | 默认规则**误点**或**完全不生效**时 |
| `keywords_append` | 追加到默认规则后面 | 默认规则**部分生效**，只需**补充**额外关键词时 |

---

### 2. 弹窗规则

```json
{"popup_rules":[{"id":"xxx","action":"xxx"}]}
```

**什么时候用？** 想关闭 App 内部的弹窗广告或更新提示时。

**规则示例：** 关闭抖音的「检测到更新」弹窗

```json
{"popup_rules":[{"id":"检测到更新","action":"以后再"}]}
```

**这条规则的意思是：** 当屏幕出现「检测到更新」这几个字时，自动点击「以后再」按钮。

> 💡 **为什么用「以后再」而不是「以后再说」？** 因为规则默认是**模糊匹配**，写成「以后再」也能匹配到「以后再说」，还能匹配其他类似的按钮文字。但如果你想让匹配更精确，可以参考下面的匹配模式。

::: tip 模糊匹配
规则里的文字默认是**模糊匹配**的——只要按钮文字包含你写的文字，就算匹配成功。

比如你写 `{"id":"以后"}`，可以匹配到「以后再说」、「以后再聊」、「以后提醒我」等多个按钮。
:::

**匹配模式进阶：** 如果你想让匹配更精确，可以在文字前加符号：

| 符号 | 模式 | 说明 | 示例 |
|------|------|------|------|
| `+` | 开头匹配 | 文字以 xxx 开头 | `+检测到` 匹配「检测到新版本」 |
| `-` | 结尾匹配 | 文字以 xxx 结尾 | `-用户体验` 匹配「改善用户体验」 |
| `=` | 完全匹配 | 文字必须完全相等 | `=以后再说` 只匹配「以后再说」 |
| `&` | 且（组合条件） | 同时满足多个条件 | `+检测到&-用户体验` |

::: example 举例张三
假设弹窗文字是「检测到新版本，为了更好的用户体验，请立即更新」，你想关闭它但**只匹配同时包含「检测到」开头和「用户体验」结尾**的文字：

```json
{"popup_rules":[{"id":"+检测到&-用户体验","action":"=以后再说"}]}
```
:::

### 遇到叉号 ❎ 关闭按钮怎么办？

有些弹窗的关闭按钮不是文字，而是一个 **✕** 图标，比如美团的天天神券弹窗。

**分两种情况处理：**

**情况一：可以用手机返回键关闭**

```json
{"popup_rules":[{"id":"=天天神券","action":"GLOBAL_ACTION_BACK"}]}
```

> 💡 `GLOBAL_ACTION_BACK` 是固定写法，意思是模拟按下手机的“返回”键。

**情况二：不可以用返回键关闭**

需要找到叉号按钮的 `id` 或 `bounds`：

```json
{"popup_rules":[{"id":"=天天神券","action":"tv_close_button"}]}      // 用 id
{"popup_rules":[{"id":"=天天神券","action":"500,900,620,1020"}]}    // 用 bounds
```

### 3. 设置强制点击

```json
{"click_way_popup":1}
```

**什么时候用？** 规则写对了，弹窗**闪了一下但没关掉**，此时可以开启强制点击，让李跳跳用更“暴力”的方式点击。

---

### 4. 设置搜索次数

```json
{"search_times_popup":5}
```

**什么时候用？** 弹窗出现后李跳跳**找不到**你指定的按钮。

**参数含义：** 李跳跳会每隔一小段时间去屏幕上找一次按钮，`search_times_popup` 就是最多找几次。

> 💡 `search_times_popup` 越小越省电，建议设置为 **3~10** 之间的数字。

👉 [详情参考：我的规则正确，但无法关闭弹窗怎么办？](#1-我的规则正确但无法关闭对应弹窗怎么办)

### 5. 设置延迟点击

```json
{"delay":200}          // 开屏广告延迟 200 毫秒
{"delay_popup":200}    // 弹窗延迟 200 毫秒
```

**什么时候用？** 广告上的「跳过」按钮**不是立即出现**，需要等一两秒才显示。

> 💡 单位是**毫秒**，1秒 = 1000毫秒。`200` 表示延迟 0.2 秒。

---

### 6. 设置点击次数

```json
{"popup_rules":[{"id":"xxx","action":"xxx","times":2}]}
```

**什么时候用？**

- `times: 0` → 规则不点击任何东西，只用来匹配弹窗状态（配合联合规则使用）
- `times: 2` → 同一个规则需要点击两次（比如两个类似弹窗一起出现）

---

### 7. 联合规则

```json
{"unite_popup_rules":true}
```

**什么时候用？** 任务需要**等待一段时间**才能完成，比如“倒计时 100 秒后点击”、应用自动安装、微信查看多张原图。

**场景举例：** 有一个按钮需要倒计时 100 秒后才能点击

**规则拆解：**

| 步骤 | 规则作用 | 代码 |
|------|----------|------|
| 第1条 | 匹配中间状态（倒计时中），但不点击 | `{"id":"还剩&秒","action":"还剩&秒","times":0}` |
| 第2条 | 匹配最终状态，点击目标按钮 | `{"id":"弹窗","action":"关闭按钮"}` |
| 参数 | 告诉李跳跳这是联合任务 | `"unite_popup_rules": true` |

**完整规则：**

```json
{
  "popup_rules": [
    {"id":"还剩&秒","action":"还剩&秒","times":0},
    {"id":"弹窗","action":"关闭按钮"}
  ],
  "unite_popup_rules": true
}
```

> 💡 `times: 0` 表示只匹配但不点击，确保李跳跳一直等待倒计时结束，而不是提前点击无效按钮。

::: tip 温馨提示
利用联合规则可以完成很多**耗时不确定的任务**，比如应用自动安装、微信自动查看多张原图等。
:::

### 8. 根据 CheckBox 的状态点击控件

**CheckBox 是什么？** 就是 App 里常见的「☑ 我同意」这种勾选框。

`CheckBox` 有两种状态：**选中**（打勾）和**未选中**（空白）。

**如何使用？** 在 `bounds` 后面加数字 0 或 1：

```json
"100,200,300,400,1"    // 点击选中状态
"100,200,300,400,0"    // 点击未选中状态
```

**参数说明：** `bounds` 是按钮位置，末尾的数字是目标状态（1=选中，0=未选中）

## 什么是控件的 id 和 bounds？

> 如果你是**普通用户**，可以跳过本章节，直接用关键词匹配规则就够了。以下内容适用于遇到「没有文字的叉号按钮」时使用。

我们把 App 界面上的所有元素——按钮、图标、输入框、文字——统称为**控件**。

大部分按钮可以通过**文字**来定位，比如「取消」按钮。但有些按钮**没有文字**（比如纯图标的 ✕ 关闭按钮），这时就需要用以下两种方式定位：

| 定位方式 | 通俗理解 | 特点 |
|----------|----------|------|
| `id` | 控件的**身份证号**（开发者起的名字） | 有唯一性，但不是每个控件都有 |
| `bounds` | 控件的**位置和大小**（屏幕上的坐标范围） | 每个控件都有，但可能随屏幕变化 |

> 💡 **`bounds` 的四个数字分别代表：** 左边界、上边界、右边界、下边界的坐标。

::: tip 温馨提示
一个控件有可能没有 `id`，但**一定会有 `bounds`**。
:::

## 常见问题

### 1. 我的规则正确，但无法关闭对应弹窗怎么办？

先判断任务类型：

#### 如果是「瞬间任务」（弹窗出现后立即点击）

在确保规则正确的前提下，依次尝试：

| 现象 | 解决方案 | 代码 |
|------|----------|------|
| 弹窗**闪了一下**但没关 | 开启强制点击 | `{"popup_rules":[], "click_way_popup":1}` |
| 弹窗**根本没反应** | 增加搜索次数 | `{"popup_rules":[], "search_times_popup":5}` |

> 💡 `search_times_popup` 越小越省电，推荐 **5~10** 次。

#### 如果是「持续任务」（需要等待一段时间）

参考上面的 [联合规则](#7-联合规则) 章节。

---

### 2. 出现误点怎么办？（点错了地方）

**排查步骤：**

1. **先删自定义规则** → 看是否是自己的规则写错了
2. **加入白名单** → 在「李跳跳」App 里找到目标 App，加入白名单（跳过所有规则）
3. **覆盖默认规则** → 自己指定点击位置，不依赖默认规则：

```json
{"keywords":["500,900,620,1020"]}
```

---

### 3. 不知道某个弹窗属于哪个 APP 怎么办？

使用 `autojs` 获取弹窗上**任意一个控件**的「控件信息」，找到其中的 `packageName`（包名），然后在李跳跳里搜索这个包名即可。

```
// autojs 显示的控件信息示例
packageName: com.example.someapp
```
